# docs/plan/

Detailed execution and build-out plans for AI and humans.

**Policy:** [ai-docs-workspace](../../../rules/ai-docs-workspace.md) · [workboard](../../../rules/workboard.md)  
**Control surface:** root `PLAN.md` (mission, stages, Agent models)—do not move Agent models here.  
**Live execution:** `docs/WORKBOARD.md` — a file in this folder is **active multi-phase work** only if the board’s Optional annex field links it.

## Conventions

- Use for multi-step / durable execution detail (options, PR breakdown, ordered tasks).  
- Multi-file program annex: `docs/plan/<program-id>/` while **open**; `git mv` to `docs/plan/archive/<program-id>/` on program complete.  
- Skeletons: [TEMPLATE-PROGRAM-README.md](./TEMPLATE-PROGRAM-README.md) · [TEMPLATE-OOO.md](./TEMPLATE-OOO.md).  
- Link root `PLAN.md` when Instruct or stages apply.  
- Promote durable stage/mission changes **into** `PLAN.md`.  
- Status each plan: `draft` / `active` / `done` / `archived`.  
- Alternate folder names (e.g. `docs/planning/`) are allowed if the authority map records them.
