# Changelog

History of the Repository Standards Kit. The kit version is the latest dated section under `## repo-kit`. Upstream: https://github.com/shainemeister/repo-kit.

An adopting project keeps its own changelog. It records the adopted kit version in the [kit baseline](./RULES.md#kit-baseline). An entry here summarizes a notable change. The commit holds the detail ([versioning](./rules/versioning-and-git.md)). Patch releases that share a day with a section below are in the git history.

Upgrades: [UPGRADE.md](./UPGRADE.md).

## repo-kit

### [3.9.0] - 2026-10-19

Platform packs record a pin in the family table and follow the author checklist, a copied skill does not require the shelf, and the closed repair queue and the shipped rework record are deprecated.

### [3.8.1] - 2026-10-18

A named program is filed only when it has no open phase, the phase table links the file each phase edits, a registered phase has a draft, a seed may omit Must, the emit table includes the path and index seeds, and a moving source pin can capture a successor.

### [3.8.0] - 2026-10-17

Path rules are `path-pattern.md` and `directory-index.md`, procedure packs live in `kit/skills/`, adopt and upgrade stay on the shelf, the root workboard is filed in the commit that finishes a program, and project agents live under `docs/library/agent-skills/`.

### [3.0.0] - 2026-10-13

The kit core is the hub, path rules, contracts, commit messages, versions, README shape, and a short install. An adopted repository keeps `UPGRADE.md` and the kit baseline. Its session order comes from `kit/templates/TEMPLATE-AGENTS.md`. Language and operating-system packs live in `library/platforms/`. Instruct and the orchestrator live in `library/skills/`.

### [2.15.0] - 2026-09-22

Optional orchestrator crew (Router, Scout, Builder, Reviewer) as explicit dispatch. It adopts the target `kit/RULES.md`.

### [2.14.0] - 2026-09-10

Programming source lives at repo-root `src/`. A segment and a module are nouns. A verb is the function.

### [2.13.0] - 2026-09-04

A commit note names the staged change. A description states what the file contains now.

### [2.11.2] - 2026-09-01

A description has to say something the title does not. When a plan annex exists, its phase brief is filled before the work is handed off.

### [2.10.0] - 2026-08-31

`files.md` owns placement and naming. Durable markdown has frontmatter except a short omit list.

### [2.8.0] - 2026-08-21

Documentation density and incorporation: cite the owner, keep the minimum core, and leave extra sections out when they do not apply.

### [2.6.3] - 2026-08-14

The root README is Overview, then Operator prompts. A coding-agent host gets a thin `AGENTS.md`. Rust and C/C++ style gates join the declared inventory.

### [2.4.0] - 2026-08-12

Live multi-phase work is recorded on `docs/WORKBOARD.md`.

### [2.3.1] - 2026-08-10

Project notes live under `docs/`. An AI-assisted commit uses `Assisted-by`, `Compliance`, and `Instructed-by`.

### [2.2.0] - 2026-08-10

When Agent Instruct is in use, the session matches one pack, opens its sources, and co-maintains the owners.

### [2.1.0] - 2026-08-05

Agent Instruct adds portable packs that cite kit law.

### [2.0.1] - 2026-07-28

Standards move under `kit/`. The project stays outside it. `UPGRADE.md` is the upgrade procedure.

### [1.2.0] - 2026-07-28

A language inventory decides which checks run. Declared checks are required before the work is called done.

### [1.1.2] - 2026-07-25

The kit baseline, this changelog, the install procedure, and the AI commit trailers are added. The baseline records the kit source so a later upgrade can find it.

### [1.0.0] - 2026-07-22

Initial portable kit: a markdown standard, a rules hub, templates, and a Python style config.
